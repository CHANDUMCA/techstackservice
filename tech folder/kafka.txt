Welcome to Apache Kafka! Learning it step-by-step is going to be fun.
Before we write any Java code, let's understand the core concepts in simple terms:
1.Producer: The application that sends messages (events).
2.Consumer: The application that receives/reads messages.
3.Topic: The category or folder name where messages are stored (e.g., a topic named my-topic).
4.Broker: The Kafka server itself that manages the topics and stores messages.

Step 4: Create the Producer Service Class (KafkaProducerService).

We will create a service class that uses Spring Boot's built-in KafkaTemplate<String, String>. This template acts like the connection manager to write messages to our Kafka topic. We will also retrieve our custom topic name (practice-topic) from application.properties using Spring's @Value annotation.

What to do:
Create a file named KafkaProducerService.java inside the src/main/java/com/sunrize/it/kafka package (absolute path: src/main/java/com/sunrize/it/kafka/KafkaProducerService.java).

Put the following code inside it:

java
package com.sunrize.it.kafka;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.stereotype.Service;
@Slf4j
@Service
public class KafkaProducerService {
    @Autowired
    private KafkaTemplate<String, String> kafkaTemplate;
    @Value("${app.kafka.topic}")
    private String topicName;
    /**
     * Publish a message to the configured Kafka topic.
     */
    public void sendMessage(String message) {
        log.info("Sending message to Kafka Topic '{}': {}", topicName, message);
        kafkaTemplate.send(topicName, message);
        log.debug("Message sent successfully to topic: {}", topicName);
    }
}

Step 5: Create a REST Controller (KafkaController).

We need an endpoint to trigger the message publication. We will expose:

POST /api/kafka/publish?message=YourMessage (Standard for writing data).
GET /api/kafka/publish?message=YourMessage (Super easy to test directly in your browser address bar).
What to do:
Create a file named KafkaController.java inside the src/main/java/com/sunrize/it/kafka package (absolute path: src/main/java/com/sunrize/it/kafka/KafkaController.java).

Put the following code inside it:
package com.sunrize.it.kafka;

import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

@Slf4j
@RestController
@RequestMapping("/api/kafka")
public class KafkaController {

    @Autowired
    private KafkaProducerService producerService;

    @PostMapping("/publish")
    public String publishMessage(@RequestParam String message) {
        log.info("Received POST request to publish message to Kafka: '{}'", message);
        producerService.sendMessage(message);
        return "Message '" + message + "' published to Kafka successfully!";
    }

    @GetMapping("/publish")
    public String publishMessageGet(@RequestParam String message) {
        log.info("Received GET request to publish message to Kafka: '{}'", message);
        producerService.sendMessage(message);
        return "Message '" + message + "' published to Kafka successfully!";
    }
}

Step 3: Create the Consumer Service Class
In your techstackservicecon project, create a file named KafkaConsumerService.java inside the src/main/java/com/sunrize/it/kafka/ directory:


package com.sunrize.it.kafka;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.kafka.annotation.KafkaListener;
import org.springframework.stereotype.Service;

@Service
public class KafkaConsumerService {

    private static final Logger log = LoggerFactory.getLogger(KafkaConsumerService.class);

    /**
     * Listen to the Kafka topic and print received messages.
     */
    @KafkaListener(topics = "${app.kafka.topic}", groupId = "${spring.kafka.consumer.group-id}")
    public void consumeMessage(String message) {
        log.info(">>>> [KAFKA CONSUMER] Successfully received message: '{}'", message);
    }
}

suppose producer service is sent a message but cosumer service will down what will happen?

This is one of the most powerful features of Apache Kafka (called Durability and Asynchronous Decoupling).

Here is what happens when the Consumer service goes down:

1. The Producer still succeeds:
Because the Producer and Consumer are completely decoupled, the Producer does not care if the Consumer is alive or dead. The Producer sends the message directly to the Kafka Broker (Docker), and Kafka saves it successfully.

2. Kafka stores the messages on disk:
Kafka stores the messages in its commit log on disk for a configured retention period (by default, Kafka keeps messages for 7 days). The messages are safe and will not be lost.

3. The Consumer catches up upon starting (Offsets/Bookmarks):
Kafka keeps track of a "bookmark" (called an Offset) for each Consumer Group (our practice-group).

While your Consumer is down, its offset stays at the last read message.
The moment your Consumer starts back up, it asks Kafka: "Are there any new messages since my last bookmark?"
Kafka sends all the missed messages to the Consumer, and the Consumer processes them in the exact order they were received!
